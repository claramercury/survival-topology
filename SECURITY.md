# Security Policy for Survival Topology

The **Survival Topology** project takes security seriously. This document outlines the security policies and procedures for reporting vulnerabilities in our control theory framework, specifications, and related artifacts.

## Reporting a Vulnerability

**DO NOT OPEN PUBLIC ISSUES FOR VULNERABILITY REPORTS.**

We use GitHub's private vulnerability reporting to ensure that security issues are handled responsibly and privately. Publicly disclosing a vulnerability before it has been addressed can put the project and its users at risk.

If you believe you have found a security vulnerability in the Survival Topology documentation or conceptual framework, please report it privately:

1. Navigate to the **Security** tab of this repository.
2. Click on **Advisories** in the sidebar.
3. Click the **Report a vulnerability** button.
4. Fill out the form with a clear description of the vulnerability, its potential impact, and any steps required to reproduce or verify it.

### What to Include in Your Report

To help us validate and fix the issue quickly, please include:

- A description of the vulnerability and its impact.
- The specific files or conceptual modules (e.g., WHO, WHERE, WHAT, etc.) affected.
- A proposed fix or mitigation, if you have one.

## Supported Versions

Currently, the Survival Topology project is in Draft (Version 1.0). Only the `main` branch is actively supported with security updates.

| Version | Supported          |
| ------- | ------------------ |
| 1.0     | :white_check_mark: |
| < 1.0   | :x:                |

## Responsible Disclosure

By participating in this project, you agree to follow responsible disclosure practices. This means allowing the maintainers a reasonable amount of time to evaluate and address the issue before making any information public.

Thank you for helping keep the Survival Topology project secure!
