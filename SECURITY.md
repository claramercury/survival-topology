# Security Policy for Survival Topology

Thank you for contributing to Survival Topology! The security of this project is a top priority. This document provides instructions on how to report vulnerabilities and outlines our security policies.

## Supported Versions

Currently, the `main` branch containing the conceptual documentation for Survival Topology is supported. If you find vulnerabilities or issues regarding the conceptual architectural security principles, please report them.

| Version | Supported          |
| ------- | ------------------ |
| 1.0     | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

We employ private, responsible disclosure practices. We request that you **do not** open public issues or pull requests to report security vulnerabilities, as this could expose users to risk before a fix is available.

Please email your findings directly to the project author, Eric Lin, at:

**[eric26752196@gmail.com](mailto:eric26752196@gmail.com)**

### What to Include in Your Report

To help us resolve the issue quickly, please provide the following details in your email:

* A clear description of the vulnerability.
* Steps to reproduce the vulnerability (or the relevant concepts from the documentation).
* Any potential impact or risk associated with the vulnerability.
* (Optional) Suggestions on how to fix the issue.

### Our Response Process

1. **Acknowledge:** We will try to acknowledge receipt of your vulnerability report within 48 hours.
2. **Investigate:** We will investigate the issue and determine its validity and severity.
3. **Remediate:** We will develop a fix and test it thoroughly.
4. **Disclose:** Once the fix is applied and published, we will publicly acknowledge your contribution (if desired).

## Security Best Practices

When contributing to this repository or building upon the Survival Topology concepts, please keep the following security principles in mind:

* **Follow Markdownlint:** Ensure all documentation complies with the `markdownlint` rules defined in `.markdownlint.json`.
* **Privacy First:** Do not commit private user documents, external assets, or confidential plans.
* **Defense in Depth:** Even for conceptual systems like the Wh- Protocol, consider security at every layer.

Thank you for helping keep Survival Topology secure!
