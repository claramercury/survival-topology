# Security Policy for Survival Topology

## Supported Versions

Since Survival Topology is an open-ended conceptual framework defining theoretical control layers for Artificial General Intelligence (AGI) and operates via theoretical documentation, only the current version (`main` branch) is supported for security vulnerability reporting. We strongly encourage focusing on theoretical vulnerabilities in the AGI architecture, or critical project repository issues.

| Version | Supported          |
| ------- | ------------------ |
| Draft 1.0 (main) | :white_check_mark: |
| Older Drafts | :x:                |

## Reporting a Vulnerability

We take the security of both the "Wh- Protocol" framework and its underlying repository seriously.

If you discover a vulnerability either within the codebase or a theoretical exploit that fundamentally compromises the "Wh- Protocol" control loop constraints (e.g., bypassing the identity gravity ($I$) or pain feedback ($E$)), **do not open a public issue.**

Instead, please practice private responsible disclosure.

Contact the author, Eric Lin, directly via email:
**[eric26752196@gmail.com](mailto:eric26752196@gmail.com)**

### What to Include in Your Report

When reporting a vulnerability, please include:

- A clear description of the vulnerability or theoretical exploit.
- Steps to reproduce the issue (or a formal mathematical/logical proof if theoretical).
- The potential impact of the vulnerability.
- Your assessment of the severity.

We will endeavor to respond to your report promptly, confirm receipt, and outline the timeline for evaluating and addressing the reported issue.
