# Security Policy for Survival Topology

## Supported Versions

Only the latest commit on the `main` branch is supported for security updates.

| Version | Supported          |
| ------- | ------------------ |
| `main`  | :white_check_mark: |
| Older   | :x:                |

## Reporting a Vulnerability

Security is a critical aspect of the Survival Topology documentation framework. If you discover any security vulnerabilities, conceptual architecture weaknesses, or potential exploit vectors within the 'Wh- Protocol', we ask that you practice responsible disclosure.

**Do not open a public issue for a vulnerability.** Publicly disclosing a vulnerability can put the project at risk.

Instead, please privately report all vulnerabilities via email to the author, Eric Lin, at:
**`eric26752196@gmail.com`**

### What to include in your report

When reporting a vulnerability, please provide the following details to help us investigate:

- **Type of vulnerability** (e.g., architectural flaw, missing validation, sensitive data exposure).
- **Location of the vulnerability** (e.g., specific section of a markdown file, conceptual module).
- **Impact** (What could an attacker achieve? How does it affect the theoretical integrity?).
- **Proof of Concept (PoC) or reproduction steps** (Detailed instructions or scenarios).
- Any potential mitigations or suggested fixes.

We will review your report and respond as quickly as possible to discuss the remediation process.
