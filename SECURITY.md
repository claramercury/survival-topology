# Security Policy for Survival Topology

The Survival Topology project values the security and integrity of its "Wh- Protocol" control theory framework and related resources. We appreciate the efforts of the security community and researchers in helping us improve the conceptual architectural security principles and documentation of this project.

## Supported Versions

Currently, the master documentation representing the core Survival Topology concepts is supported for security updates:

| Version | Supported          |
| ------- | ------------------ |
| 1.0     | :white_check_mark: |

## Reporting a Vulnerability

As the Survival Topology model introduces a closed-loop control system addressing the open-loop problems of current AGI architectures, maintaining the integrity of this framework is critical.

If you discover a vulnerability or security-related issue in the Survival Topology documentation, architectural concepts, or potential implementations of the Wh- Protocol, we mandate a **private responsible disclosure** process.

**Please do not open a public issue.** Public disclosure of security issues before they are addressed can present risks to the integrity of the framework.

Instead, please report any security vulnerabilities directly to the author, Eric Lin, via email:

* **Contact Email:** [eric26752196@gmail.com](mailto:eric26752196@gmail.com)

When reporting a vulnerability, please include the following information:

* A description of the vulnerability and its potential impact on the Survival Topology framework.
* Detailed steps to reproduce or identify the issue.
* Any relevant suggestions or architectural mitigations, particularly relating to the Seven Seals (WHO, WHERE, WHAT, WHICH, HOW, WHEN, WHY) if applicable.

You should receive an acknowledgment of your report within 48 hours, and we will work with you to address and safely mitigate the reported issue.
