# Security Policy for Survival Topology

## Supported Versions

Currently, the Survival Topology documentation and conceptual framework are actively maintained. While this repository primarily contains theoretical concepts and markdown documentation, security is paramount to the integrity of the project.

| Branch / Version | Supported          |
| ---------------- | ------------------ |
| `main`           | :white_check_mark: |
| Other branches   | :x:                |

## Reporting a Vulnerability

We take the security of the Survival Topology framework and the Wh- Protocol very seriously. If you discover a vulnerability or security issue within the conceptual architecture, documentation, or associated repositories, please do not disclose it publicly.

We ask that you practice **private responsible disclosure**. Please email the author directly:

**Contact:** Eric Lin
**Email:** eric26752196@gmail.com

When reporting a vulnerability, please include:

- A detailed description of the vulnerability or security flaw.
- Steps to reproduce or understand the issue.
- Potential impact on the Survival Topology architecture or implementation.
- Any suggested mitigations or fixes.

We will acknowledge receipt of your vulnerability report and work diligently to address the issue before any public disclosure is made.

## Principles

Our security approach aligns with the core principles of the Wh- Protocol:

- **Pain (Feedback):** We value feedback on vulnerabilities as essential for correcting our system state.
- **Identity (Gravity):** Security enhancements preserve the core identity and safety of the framework.

Thank you for helping keep the Survival Topology project secure!
