# Security Policy for Survival Topology

Thank you for your interest in the security of the Survival Topology project. As an architecture that explores the boundaries between conceptual theoretical models (The Wh- Protocol) and closed-loop control systems, we take the integrity and conceptual security of the framework seriously.

## Supported Versions

Because the `main` branch currently acts exclusively as the repository for the theoretical "Survival Topology" markdown documentation and lacks a corresponding code execution environment, there are no active runtime versions to support. Security updates and reviews will apply to the latest documentation revisions directly on the `main` branch.

| Version | Supported          |
| ------- | ------------------ |
| `main`  | :white_check_mark: |

## Reporting a Vulnerability

We strongly encourage the private and responsible disclosure of security issues. If you identify an issue related to:

* Conceptual or mathematical exploitation models in the protocol design
* Exploits that could arise from theoretical implementations of the seven physical dimensions (WHO, WHERE, WHAT, WHICH, HOW, WHEN, WHY)
* Information leaks or documentation vulnerabilities within the Markdown structure

**Do NOT open a public issue.** Public disclosure of unpatched conceptual exploits can be detrimental to ongoing research.

Instead, please report any suspected vulnerabilities privately by contacting the project author, Eric Lin, via email at:
**[eric26752196@gmail.com](mailto:eric26752196@gmail.com)**

### What to include in your report

When reporting an issue, please include:

* A detailed description of the vulnerability or theoretical exploit
* The potential impact on the conceptual integrity or potential future implementations of the Wh- Protocol
* Proposed mitigation strategies or mathematical corrections

We will acknowledge receipt of your vulnerability report and will strive to provide updates as we review your submission.

## Non-Security Issues

For standard typos, formatting issues, or general theoretical discussions that do not pose a direct conceptual security threat, please feel free to open a regular public pull request or issue.
