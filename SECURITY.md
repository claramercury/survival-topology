# Security Policy

## Supported Versions

Currently, the "Survival Topology" conceptual framework and any associated future code implementations are actively maintained.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

Security is a fundamental consideration in the design of the Wh- Protocol and the Survival Topology architecture.
If you discover a security vulnerability or a theoretical flaw that could lead to unexpected behavior in our control theory framework, we kindly ask that you report it privately.

**Please do not report security vulnerabilities through public GitHub issues.**

Instead, report them privately via email to the project author, Eric Lin, at `eric26752196@gmail.com`.

### What to include in your report

- A detailed description of the vulnerability or architectural flaw.
- Steps to reproduce or theoretical proofs, if applicable.
- Any potential impact on the system's "Identity State" or closed-loop feedback mechanism.

You should receive a response within 48 hours acknowledging receipt of the vulnerability report. The author will work with you to understand the issue, determine its priority, and develop a patch or theoretical revision before public disclosure.
