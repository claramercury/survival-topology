# Security Policy for Survival Topology

Thank you for your interest in the security of the Survival Topology project. As an architectural and conceptual framework detailing a closed-loop control system for AGI, the integrity of the Wh- Protocol principles is essential.

## Supported Versions

Currently, this repository functions primarily as theoretical documentation outlining the Wh- Protocol, the 7 Seals, and existential feedback loops. The principles discussed are actively evolving. All security enhancements and architectural corrections should be targeted at the active `main` branch.

| Branch/Version | Supported          |
| -------------- | ------------------ |
| `main`         | :white_check_mark: |
| legacy forks   | :x:                |

## Reporting a Vulnerability

**DO NOT** open public issues for security vulnerabilities, architectural flaws that could compromise the integrity of the Wh- Protocol, or theoretical exploits in the Survival Topology design. Public disclosure could cause unnecessary confusion or premature assumptions regarding the project's foundational logic.

Instead, please practice private, responsible disclosure.

1. **Contact:** Send an email directly to the project author, Eric Lin, at `eric26752196@gmail.com`.
2. **Details:** Please include a detailed description of the theoretical vulnerability or architectural gap. If your report includes proposed solutions (e.g., changes to how Pain/Feedback ($E$) is modeled), please attach your theoretical models or mathematical proofs.
3. **Process:** The author will review the submission, typically within 72 hours, to assess its implications on the closed-loop system design. We will maintain communication with you throughout the evaluation and patching process.

We deeply appreciate your efforts in securing the theoretical foundation of AGI.
