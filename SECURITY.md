# Security Policy for Survival Topology

## Supported Versions

Currently, the `main` branch (which contains the conceptual "Survival Topology" architecture) and the `android` branches are actively maintained. However, security updates for the documentation focus strictly on mitigating realistic risks associated with these documents.

| Version | Supported          |
| ------- | ------------------ |
| 1.0     | :white_check_mark: |

## Reporting a Vulnerability

As the Survival Topology project contains conceptual architecture rather than executable binaries in the main repository, vulnerabilities would typically pertain to:

- Social engineering risks or logical flaws in the Wh- Protocol theoretical definitions.
- Issues with the build systems or tools associated with the documentation pipeline.

**Do not open public issues for security vulnerabilities.**

If you discover a vulnerability or security risk, please practice responsible disclosure.

1. Email the project author, Eric Lin, directly at **eric26752196@gmail.com**.
2. Include "[SECURITY]" in the subject line.
3. Provide a clear description of the vulnerability, potential impact, and instructions on how to reproduce the issue.

We will acknowledge receipt of your vulnerability report within 72 hours and provide an estimated timeline for resolution. Public disclosure should be delayed until an appropriate fix or mitigation has been applied to the repository.
