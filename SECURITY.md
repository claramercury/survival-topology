# Security Policy for Survival Topology

Thank you for your interest in improving the security of the **Survival Topology** framework. While this repository primarily contains conceptual and philosophical documentation regarding the "Wh- Protocol" and autonomous agency, we still take security very seriously.

Given the theoretical nature of this project and potential implications for advanced autonomous systems (AGI), securing the underlying framework and ensuring safe control parameters is paramount.

## Supported Versions

Currently, the Survival Topology framework is in its **Draft (Version 1.0)** phase. We will provide updates on supported versions as the framework evolves and moves toward implementation phases.

| Version | Supported          |
| ------- | ------------------ |
| 1.0     | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

As this framework deals with foundational control mechanisms for autonomous systems (such as the "Pain Feedback" $E$ loop and the "Identity Gravity" $I$ anchor), we handle all security-related discoveries with strict confidentiality.

**DO NOT create a public issue to report a security vulnerability.**

Instead, please practice private responsible disclosure to ensure that vulnerabilities are addressed without exposing the framework to potential exploitation or misinterpretation.

### How to Report

1. **Use GitHub Private Vulnerability Reporting:** If enabled on this repository, please navigate to the "Security" tab and use the "Report a vulnerability" feature to privately submit your findings to the maintainers.
2. **Maintainer Contact:** Alternatively, if private reporting is unavailable, reach out to the core maintainers privately regarding critical flaws in the architectural logic or control equations.

### What to Include

When reporting an issue, please provide:

* A clear description of the vulnerability, whether conceptual (e.g., a flaw in the control loop logic) or technical.
* The potential impact of the vulnerability.
* Proposed fixes or mitigating strategies (if applicable).

We will evaluate reports and aim to respond promptly, acknowledging the contribution and outlining our plan for addressing the issue.
