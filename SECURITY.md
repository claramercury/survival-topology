# Security Policy

## Supported Versions

Currently, the Survival Topology framework and its corresponding theoretical documentation (v1.0) are maintained and supported for security updates.

| Version | Supported          |
| ------- | ------------------ |
| 1.0     | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

Security is a fundamental concern within the Survival Topology ecosystem. We take all security vulnerabilities seriously and appreciate your efforts to responsibly disclose findings.

**Do not open a public issue on GitHub** to report a security vulnerability, as this may expose the vulnerability details before a fix can be applied.

Instead, please adhere to the following responsible disclosure guidelines:

1. **Private Disclosure:** Please report all suspected security vulnerabilities directly to the author, Eric Lin, via email at eric26752196@gmail.com.
2. **Details:** Include as much information as possible in your report, such as:
    * A description of the vulnerability and its potential impact.
    * Detailed steps to reproduce the issue.
    * Any relevant logs, conceptual flaws in the theoretical framework, or code snippets if applicable.
3. **Response:** We aim to acknowledge receipt of your vulnerability report within 48 hours and will provide regular updates on the progress of a fix.
4. **Public Disclosure:** We kindly request that you wait until a fix has been deployed and public announcement has been made before publicly disclosing the vulnerability details.

We appreciate your cooperation in helping keep the Survival Topology project secure!
