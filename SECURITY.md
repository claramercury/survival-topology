# Security Policy

The following versions of the Survival Topology documentation are currently receiving security updates:

| Version | Supported          |
| ------- | ------------------ |
| 1.0     | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

Security is a primary concern for the Survival Topology framework. We appreciate the efforts of security researchers and users who help us identify and address potential vulnerabilities.

**Please do not report security vulnerabilities through public GitHub issues.**

If you believe you have found a security vulnerability in the Survival Topology documentation or associated theories that could be exploited maliciously (such as conceptual loopholes that could lead to unsafe AI behavior), please report it to us privately.

### Responsible Disclosure Process

1. **Email:** Send your report directly to Eric Lin at `eric26752196@gmail.com`.
2. **Details:** Include a detailed description of the vulnerability, the potential impact, and any steps to reproduce or exploit it. If applicable, please include the relevant section or equation of the "Wh- Protocol" that contains the vulnerability.
3. **Response:** We will acknowledge receipt of your vulnerability report within 72 hours.
4. **Resolution:** We will work diligently to investigate the issue and develop a fix or mitigation strategy. We will keep you informed of our progress.
5. **Disclosure:** Once the issue has been resolved, we will coordinate public disclosure (if appropriate) to ensure the safety of all users and systems implementing this framework.

Thank you for your help in keeping the Survival Topology project secure.
