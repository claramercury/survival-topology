# Security Policy for Survival Topology

This project, **Survival Topology: A Control Theory Framework for General Intelligence**, is currently a theoretical, markdown-based documentation repository proposing a new architecture for Large Language Models (LLMs) and Artificial General Intelligence (AGI).

As a theoretical framework focusing on the "Wh- Protocol" and Existential Feedback loops, the scope of security for this specific repository is unique.

## Scope of Security

This repository does not contain production software, APIs, or functional applications. Therefore, traditional software vulnerabilities (like XSS, SQLi, or API key exposure) are largely out of scope for the contents of this repository itself.

However, we consider the following to be **IN SCOPE** for security considerations and reporting:

1.  **Theoretical Vulnerabilities in the Control System:** Identifications of critical flaws in the proposed "Survival Topology" architecture that could lead to unrecoverable "hallucination," reward hacking, or misalignment within the hypothetical closed-loop system.
2.  **Information Hazards:** Accidental inclusion of sensitive or hazardous theoretical constructs that could be misused if implemented in a real-world AGI system without proper safeguards.
3.  **Repository Security:** Any misconfiguration of the repository itself (e.g., exposed theoretical assets, unauthenticated access to project planning documents if they are added).

## Out of Scope

The following are generally considered out of scope, unless they directly impact the theoretical integrity of the proposed framework:
*   Vulnerabilities in the Python simulation script provided in the README (it is a rudimentary demonstration, not production code).
*   Standard web vulnerabilities, as this is not a web application.

## Reporting a Vulnerability

We take the theoretical integrity and safety of the Survival Topology framework seriously.

If you identify a critical flaw in the architecture or a potential information hazard, please report it to us securely.

**Do not open a public issue.**

Instead, please use **GitHub Private Vulnerability Reporting**.
1. Navigate to the **Security** tab of this repository.
2. Click on **Advisories** in the left sidebar.
3. Click on the **Report a vulnerability** button.
4. Provide a detailed description of the theoretical flaw or hazard.

Our research team will review the report and coordinate with you on any necessary updates to the theoretical framework. We aim to acknowledge reports promptly and will prioritize critical architectural flaws.
