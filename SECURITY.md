# Security Policy for Survival Topology

Thank you for your interest in the security of the Survival Topology and the Wh- Protocol framework. This document outlines our security policies and reporting procedures.

## Scope

The current main branch is focused on theoretical control theory, architectural definitions of the "Wh- Protocol", and mathematical proofs related to Survival Topology. As such, security vulnerabilities in this domain typically relate to:

- Theoretical or mathematical flaws in the proposed closed-loop control system that could cause catastrophic divergence.
- Exploitable logic in the 7 physical dimensions (WHO, WHERE, WHAT, WHICH, HOW, WHEN, WHY) that could allow malicious input ($\Omega$) to bypass the error signal ($E$).
- Documentation issues that could lead to insecure physical implementations of the agent's "Identity State" ($I$).

Note: If you are looking for the security policy of the 'Bookhook' Android application, please refer to its respective branch.

## Reporting a Vulnerability

**Please DO NOT report security vulnerabilities through public GitHub issues.**

We strictly mandate private responsible disclosure for any findings that could compromise the integrity of the Wh- Protocol or its implementations.

If you believe you have found a security vulnerability, please report it via one of the following private channels:

1. **Email:** Contact the project author, Eric Lin, directly at `eric26752196@gmail.com`.
2. **GitHub Private Vulnerability Reporting:** If enabled on this repository, please use the private reporting feature under the "Security" tab.

### What to Include

When submitting a report, please provide a detailed description of the issue, including:

- A summary of the vulnerability.
- The specific theoretical or documentation component affected (e.g., The "WHAT" Pain Feedback Module).
- Step-by-step instructions to reproduce the vulnerability or a mathematical proof demonstrating the flaw.
- The potential impact on the system's "Identity State" or "Existential Feedback" loop.
- Any suggested mitigations.

We take all reports seriously and will respond to your disclosure as quickly as possible to discuss the findings and our mitigation plan.
