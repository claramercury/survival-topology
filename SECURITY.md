# Security Policy for Survival Topology

This project, **Survival Topology**, is currently a theoretical and
architectural framework for a closed-loop Artificial General Intelligence
(AGI) control system. As it is a documentation repository, its security
primarily concerns the integrity, safety, and ethical implications of the
mathematical and logical models proposed.

## Supported Versions

Currently, there are no executable builds or software releases for this
project. The documentation is maintained in ongoing drafts.

| Version | Status |
| :--- | :--- |
| Draft (main branch) | Supported |
| Previous Drafts | Not Supported |

## Reporting a Vulnerability

If you identify a logical flaw, theoretical exploit, or architectural
vulnerability within the "Wh- Protocol" (such as a way an agent could
bypass the Existential Feedback loop or manipulate the Identity Gravity
vector), please report it responsibly.

**How to Report:**

1. Do **not** open a public issue for severe theoretical vulnerabilities
   (e.g., an uncontainable optimization loop).
2. Email your findings to the repository maintainers directly with the
   subject line `[SECURITY] Survival Topology Vulnerability Report`.
3. Include a clear description of the logical flaw and, if possible, a
   mathematical or conceptual proof of the exploit.

We will acknowledge your report within 48 hours and coordinate with you on
updating the theoretical model to address the identified risk before any
public disclosure.

## Architectural Security Principles

This framework prioritizes security by design through its core components:

* **Simulation Sandboxing:** The "WHICH" module strictly isolates
  counterfactual planning (Imaginary Time) from execution (Real Time).
* **Identity Constraints:** The "WHO" module acts as a non-bypassable core
  directive, preventing arbitrary goal modification.
* **Existential Feedback:** The system requires continuous validation against
  objective reality, mitigating unconstrained hallucination or thermal
  runaway.
