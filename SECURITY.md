## 1. Scope

This document outlines the security policies, disclosure guidelines, and risk framework for the **Survival Topology** repository. The scope currently covers:

- The "Survival Topology" conceptual documentation and the "Wh- Protocol" framework.
- Any future conceptual models or proofs integrated into this theoretical framework.

*Note: The `main` branch exclusively contains theoretical and conceptual documentation. Security issues concerning Android applications should be routed to their respective application branches.*

## 2. Reporting a Vulnerability

We prioritize a secure and safe theoretical environment for control theory frameworks. We strongly encourage private, responsible disclosure of any security vulnerabilities, architectural flaws, or conceptual bypasses related to the "Survival Topology" framework.

**How to Report:**

1. **Do NOT open a public issue** if the vulnerability exposes sensitive implementation details, architectural flaws that could be maliciously adapted, or presents a tangible risk to generalized intelligence architectures.
2. Please use GitHub's **Private Vulnerability Reporting** feature to submit your findings confidentially to the maintainers.
3. Include a detailed description of the vulnerability, potential impact, and step-by-step instructions or mathematical models to reproduce the issue.

We will review reports and coordinate with you on the mitigation and timeline for public disclosure.

## 3. Threat Model

The primary threats to this theoretical framework currently involve:

- **Conceptual Integrity:** Ensuring the "Wh- Protocol" (WHO, WHERE, WHAT, WHICH, HOW, WHEN, WHY) cannot be logically bypassed to cause open-loop AI divergence (hallucination/thermal runaway).
- **Identity Poisoning:** Risks to the "WHO" (Identity / Gravity / $I$) prompt vector that could alter the agent's core values.
- **Feedback Manipulation:** Attacks on the "WHAT" (Pain / Feedback / $E$) signal that could falsify error detection.
- **Simulation Evasion:** Flaws in the "WHICH" (Simulation / $i$) layer that allow malicious execution paths to leak into Real Time ($R$).

## 4. Security Philosophy

We operate on the principle that **Intelligence is not merely the processing of information; it is the ability to resist entropy.**

- **Defense in Depth:** The 7 seals of the Wh- Protocol must mutually verify each other.
- **Existential Feedback:** The framework must guarantee that deviations from reality incur a measurable, non-bypassable cost ("Pain").
- **Immutable Core:** The system's identity ($I$) must be hardened against external manipulation.
